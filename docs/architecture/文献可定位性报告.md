# 文献可定位性报告

> 由 `node scripts/report_source_locatability.js` 生成，数据源为 CBDB 的
> `KIN_DATA` 与 `TEXT_CODES` 两表。本文件记录 2026-10 的快照与结论。

## 为什么需要这份报告

编辑功能（后续 S3）要求「读取原文并划取式抽取」。前提是能从一条断言
定位到原文的某一处——没有页码/条目号，「划取」就无从谈起。

所以先回答一个问题：**CBDB 给的这些断言，有多少能追到原文？**

## 总览

| 指标 | 数值 |
| --- | --- |
| KIN_DATA 有文献来源的行 | 485,098 |
| 其中有页码/条目号 | 413,070（**85.2%**） |
| 文献种类 | 481 |

85.2% 看着很好，但「有页码」不等于「能定位」——页码的形态决定它能否对到原文。

## 四档分类

### A 可立即做：有页码 + 在线可读（4 种，47,009 行，9.7%）

| 文献 | 行数 | 覆盖率 | 页码形态 |
| --- | --- | --- | --- |
| 人名權威資料（中研院史語所） | 34,565 | 100% | 条目序号 |
| 明清婦女著作數據庫 | 12,440 | 99% | 数据库条目 ID |
| 明文衡 | 2 | 100% | 卷/页 |
| 維基數據 | 2 | 100% | 卷/页 |

这两种大文献都有 `c_url_api`，能直接拼出在线详情页：

- 人名權威：`https://newarchive.ihp.sinica.edu.tw/sncaccgi/snca…`
- 明清婦女：`https://mhdb.mh.sinica.edu.tw/mingqing/mqww/search/details-poet.php?poetID=`

**这是唯一可以立刻做划取式抽取的一档**——有定位、有在线原文。

### B 有页码但需线下查（46 种，46,840 行，9.7%）

页码是真正的古籍卷页，能对纸书，但没有在线地址：

| 文献 | 行数 | 页码样例 |
| --- | --- | --- |
| 唐代墓誌匯編:二卷 | 29,893 | `Kaicheng 40`、`Dazhong 93` |
| 唐代墓誌彙編續集 | 13,622 | `(XJ)Xiantong8`、`Kaicheng 40` |
| 全宋文 | 1,957 | `471.21a` |
| Pers DB / 唐代人物知識ベース | 907 | — |

`Kaicheng 40` 是「开成 + 第 40 号」，对应《唐代墓誌彙編》的编排体例，
能查到纸书。做划取需要用户手上有这本书，或先扫描入库。

### C 有页码但形态是数据库 ID（328 种，320,580 行，66.1%）

页码字段填的是**对方数据库的条目号或榜次**，不是纸书位置：

| 文献 | 行数 | 页码样例 | 能对到什么 |
| --- | --- | --- | --- |
| 宋人傳記資料索引(電子版) | 11,833 | `15184` | 该数据库第 15184 条 |
| 萬曆丙戌科進士同年總錄 | 9,200 | `第三甲第四十六名` | 登科录的榜次 |
| 隆慶五年進士登科錄 | 7,794 | `第三甲第…` | 同上 |

榜次（`第三甲第四十六名`）其实**能**定位到原文——登科录就是按榜次编排的。
但需要登科录本身的文本才能划取。

条目号（`15184`）只能定位到《宋人傳記資料索引》这个数据库的记录，
要拿到原文还得看那个数据库是否开放。

### D 页码缺失（103 种，70,669 行，14.6%）

| 文献 | 行数 | 覆盖率 |
| --- | --- | --- |
| 唐五代人物傳記與社會網絡資料庫 | 54,272 | **0%** |
| 寶祐登科錄 | 9,000 | 0.2% |
| 宋史 | 3,742 | 2.5% |
| 蒙古王公表傳 | 2,264 | 0% |

最常被引的《唐五代人物傳記與社會網絡資料庫》（54,272 行）**一条页码都没有**。
它本身是个在线数据库，但 CBDB 只记了 `c_source`，没记条目号。

《宋史》3,742 行里只有 94 行有 `c_pages`（2.5%）。

## 结论

**能立刻做划取式抽取的：4 种文献，47,009 行断言（9.7%）。**

这不算少——47,009 条断言足够验证整条编辑链路（划取 → 校验 → commit → 重建）。

**如果要把覆盖率提到 50% 以上**，需要先做一件事：给 C 档的「条目号」类文献
补上在线地址。其中《宋人傳記資料索引(電子版)》（11,833 行）和各类登科录
（合计约 10 万行）是关键——它们有可定位的条目号/榜次，只缺「怎么打开」。

## 这份报告的口径修正

初版报告把「能不能找到古籍 txt」当成做划取的前提，方向错了。

按 §6.4.3 的原则，`quote` 是**原文副本**，划取只在录入后台发生一次。
所以真正需要「能打开原文」的，**只有录入那一刻**：

- **一手文献**（网页/报刊/档案）：需要打开网页、划出句子、存副本
- **二手数据库**（CBDB）：`quote` 放字段串即可，**不需要找古籍 txt**

也就是说：

| 场景 | 需要原文吗 |
| --- | --- |
| 录入 CBDB 的断言 | 不需要。字段串就是 `quote` |
| 录入网页类断言 | 需要。打开网页划取，存进 `quote` |
| **展示任何已有断言** | **都不需要**。读 `quote` 副本 |

这大幅降低了门槛：CBDB 的 81 万条出处**已经全部有 `quote`**（字段串形态），
展示侧无需任何额外工作。

## 当前真实缺口：网页类证据是空壳

实测：112 个证据节点里 **111 个没有 `excerpt`，且没有任何断言引用它们**。

```
evidence:cbdb              810,813 条出处    ← 唯一有内容的
evidence:local-000001      0 条出处，excerpt 为空
evidence:local-000003      0 条出处，excerpt 为空
…（另有 109 个同类）
```

它们只是元数据占位（标题 + URL），不是可用的出处。
真正需要补 `quote` 的是这一批——但前提是先有断言引用它们，
而目前网页抓取的内容并未进入关系层。

## 对编辑功能的影响

建议的推进顺序：

1. **先做 A 档**（人名權威 + 明清婦女，47,007 行）
   - 有在线 URL，能真正实现「点开原文 → 划取 → 提交」
   - 两种文献的页码形态不同（条目序号 vs PoetID），正好验证通用性
2. **C 档的榜次类**（登科录，约 10 万行）
   - 榜次本身是可定位的，缺的是登科录文本
   - 若能有扫描件/电子文本，这一档立刻可用
3. **D 档暂缓**
   - 《唐五代》54,272 行无页码，除非回头补 CBDB 的 `c_pages`，否则无法定位

## 复现

```bash
node scripts/report_source_locatability.js
```

输出包含每档的完整文献列表与页码形态抽样。
