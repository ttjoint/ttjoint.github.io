# HumanMap 项目架构

> 面向"历史至今的人物家谱、组织与企业关系"的可视化知识图谱。
> 本文档描述整体架构、数据模型与扩展方式。**每次结构性改动后必须同步更新本文档。**

---

## 1. 设计目标

| 目标 | 落地方式 |
| --- | --- |
| 支撑超大规模实体（当前 66 万 CBDB 人物待入库） | 分片 JSON + 派生图索引，存储与查询分离 |
| 关系词可检索、可分类、可合并 | **谓词原语注册表**（谓词即边类型） |
| 反向 / 否定语义 | 谓词前缀修饰符 `/inverse`、`/negate` |
| 任意历史时间跨度（公元前至今） | 一律以**儒略日（JDN）**存储，支持模糊区间 |
| 时段时间轴筛选 | `TimeRange{start,end,mid,uncertainty}` + 置信度分桶 |
| 可审计、可回溯 | 每条边记录 `createdAt`（录入时刻）与 `sourceUrl` |
| 静态站点可部署 | `data/` 为唯一真相，`export:*` 半自动生成站点快照 |

## 3. 数据模型

### 3.1 节点（Node）

```jsonc
{
  "id": "person:1a21a54164de8d9c0294",  // 稳定 ID：type:sha256(type\0name)[:20]
  "type": "person | organization | event",
  "name": "石泰峰",
  "aliases": ["石泰"],
  "tags": ["全国政协", "已审核"],
  "props": { "性别": "男", "出生年月": "1956年9月", "籍贯": "山西榆社" },
  "summary": "…",
  "sources": [{ "name": "全国政协官网", "url": "…", "accessedAt": "…" }],
  "lifespan": { "start": 2435731, "end": null, "mid": 2435746, "uncertainty": 0, "precision": "month" }
}
```

### 3.2 边（Edge）—— 一切关系皆为断言

```jsonc
{
  "id": "edge:<subject>|<key>|<object>|<role>|<span>",
  "key": "father",            // 谓词键，可带 /inverse 或 /negate
  "subject": "person:aaa",
  "object": "person:bbb",     // 或字符串（literal: true）
  "literal": false,
  "role": "总理",              // 限定词：官职/头衔
  "range": { "start": …, "end": …, "mid": …, "uncertainty": 0 },
  "note": "",
  "sourceUrl": "",
  "confidence": 1.0,
  "createdAt": "2026-10-17T03:00:00.000Z"   // 录入时刻
}
```

**属性也是边**：`性别`、`民族`、`学历`、`籍贯`、`出生年月` 等 scalar 值被提升为
literal 边（`gender` / `ethnicity` / `education` / `residedAt` / `birthDate`），
因此谓词检索、可视化、过滤共用同一套索引。

## 4. 谓词原语（关系词）

### 4.1 定义

谓词不是自由文本，而是注册表中的原语，具备：

| 字段 | 说明 |
| --- | --- |
| `key` | 规范键，如 `father` |
| `label` | 默认显示名，如 `父亲` |
| `domain` / `range` | 主语 / 宾语类型约束 |
| `inverse` | 反向谓词键（`father` ↔ `childOfFather`） |
| `aliases` | 同义词，检索时归一（`爸爸` → `father`） |
| `symmetric` | 自反谓词（`spouse`,`sibling`,`friend`） |
| `negatable` | 是否允许 `/negate` |
| `subjectGender` | 主语性别约束（`maleChild` = `male`） |
| `qualifiers` | 允许的限定词：`role`/`dates`/`place`/`note`/`source` |

### 4.2 修饰符而非新谓词

```
a 是 b 的父亲      →  (father,        a, b)
b 是 a 的子女      →  (childOfFather, b, a)        ← 等价，故存为 father/inverse
c 不是 b 的父亲    →  (father/negate, c, b)        ← 明确否定
```

- `/inverse` 表示该边以反向视角记录；查询 `父亲` 时同时命中 `childOfFather`。
- `/negate` 表示"明确不成立"（如"已不在该地任职"），区别于"无记录"。

### 4.3 带性别的指称

不做谓词爆炸，而用 `subjectGender` 约束：

```
儿子 = (father/inverse) 且 subject.gender == male
女儿 = (father/inverse) 且 subject.gender == female
```

因此检索"儿子"只会返回男性子女。实现见 `registry.js` 的 `maleChild` /
`femaleChild`（`genderFamily: 'child'`）。

### 4.4 同义词合并

- 内置别名在 `BUILTIN` 中声明。
- 外部扩展放 `data/predicates/registry.json`，加载时合并。
- `PredicateRegistry.suggestMerges()` 给出候选合并建议，**不自动应用**，
  由管理员确认后写入 registry.json。
- 冲突（同一别名指向两个原语）记录在 `mergeConflicts`，不静默覆盖。

## 5. 时间模型

### 5.1 儒略日

所有时刻存为 JDN（整数天）。已验证：`2000-01-01 → 2451545`、`1970-01-01 → 2440588`，
并支持公元前（天文纪年，1 BCE = 0）。后续可扩展历法/年号层，JDN 作为统一底层。

### 5.2 TimeRange

```jsonc
{ "start": 2435731, "end": 2435760, "mid": 2435746,
  "uncertainty": 0, "precision": "month", "source": "parsed" }
```

- `start`/`end`：已知边界，`null` 表示未知。
- `mid` + `uncertainty`：完全模糊时的中值点 ± 年数（如 尧 = `-1200±50年`）。
- `precision`：`exact|month|year|decade|century|approx|unknown`。
- 只知卒年时，只填 `end`，`start` 为 `null`。

### 5.3 置信度分桶（UI 三档筛选）

| 桶 | 判定 |
| --- | --- |
| `exact` | 两端均精确到日 |
| `fuzzy` | 至少一端已知，但非精确到日，或 ± 半径 < 100 年 |
| `vague` | 仅中值点且宽度大（如神话人物） |

时间轴滑块产生 `[loJdn, hiJdn]`，`QueryEngine.search({lo,hi,confidence})` 完成过滤。

## 6. 存储与查询

```
CBDB SQLite (584MB)  ─┐
官方网站抓取          ├─► 导入器 ─► 候选 JSON ─► 管理员审核 ─► SQLite(admin)
人工录入             ─┘                                              │
                                                                     ▼
                                        data/*/entities/*.json ◄─ export_static
                                                                     │
                                                     build_index ────┤
                                                                     ▼
                                              index.json + manifest.json
                                                                     │
                                                        GraphStore + QueryEngine
                                                                     │
                                                            前端 (js/)
```

- **权威源** = `data/`（Git 可回溯）。SQLite 仅作为审核工作区。
- 大规模优化：`GraphStore` 建立 `outEdges` / `inEdges` / `byPredicate` 三份内存索引，
  查询为 O(1) 定位 + O(k) 遍历；66 万节点可分批加载（见 §9）。

## 7. 前端

| 模块 | 职责 |
| --- | --- |
| `js/core/data-store.js` | 索引按需加载 + 详情分片懒加载 |
| `js/core/graph-view.js` | 力导向 / 分簇可视化 |
| `js/core/timeline.js` | 双端可拖动时间范围条 + 置信度开关 |
| `js/views/*` | 列表、详情、谓词浏览器 |

前端的筛选参数与 `QueryEngine.search()` 一一对应，便于将来把查询下沉到服务端。

## 8. 开发流程

```bash
npm run admin        # 本地审核后台 127.0.0.1:8787
npm run publish      # SQLite → data/ → 索引 → 引用检查
npm run check        # 构建 + 校验 + 测试
npm test             # 单元/集成测试
```

**改动后必做**：
1. `npm run check` 全绿
2. 更新本文件与 `docs/使用说明.md`
3. 提交（索引与 manifest 入库，分片可不入）

## 9. 大规模与扩展性

- **分批导入**：CBDB 66 万人物按朝代/年份分片导入，每批产出独立 import 批次。
- **惰性加载**：前端只加载 index.json（轻量），详情按需 fetch。
- **索引裁剪**：`index.json` 字段保持最小（id/name/type/aliases/tags/summary/lifespan）。
- **未来可选**：接入 DuckDB / SQLite graph 扩展或外部图库（Neo4j），
  `GraphSource` 接口（`src/store/`）已抽象，替换实现不影响前端。
