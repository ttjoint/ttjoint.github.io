# 实体类型重构：四类基础节点 + 证据节点

> 状态：**已完成**（步骤 1–5 全部落地，数据规模 5501 实体：5287 人 / 6 thing / 67 组织 / 30 事件 / 111 证据）。
> 目标：把「人物 / 非人实体 / 组织国家 / 事件」四类基础节点，加上「证据」节点，
> 变成系统的**一等公民**，而不是把证据塞进实体的内嵌字段。

## 1. 问题陈述

### 1.1 现状：只有三类，且证据不是节点

```
src/store/entity_writer.js:21
const FOLDERS = { person: 'persons', organization: 'organizations', event: 'events' };
```

实测分片：persons 5287 / organizations 34 / events 30，共 5351。

三个结构性缺口：

| 缺口 | 表现 |
| --- | --- |
| 没有「非人实体」 | 人民日报、某份条约、某本史书，只能塞进 `props` 自由文本，或错误地记成 organization |
| 证据不是节点 | `sources` 是实体里的内嵌数组，没有 id 空间、不能被引用、不能上图 |
| 证据主语是字符串 | `name: "最高人民检察院"` 是标签而不是实体引用；实测「人民日报」「人民日报社」「新华社」在库中均**不存在** |

证据现状（真实数据）：

```js
sources: [{
  id: "cpc-aHR0cDovL2NwYy5wZW9wbGUuY29tLmNu...",  // base64url(URL)，不是规范 id
  name: "人民网人物资料",                            // 字符串标签，不是实体引用
  url: "http://cpc.people.com.cn/n1/2023/0311/...",
  accessedAt: "2026-10-16T..."
}]
```

三处不合规：
- `id` 不是 `type:sha256(type\0name)[:20]` 规范格式，且**同一 URL 在多个实体里产生相同 id**——
  本该是一个共享节点，却是 N 份互不相关的副本。
- `name` 不指向实体，因此「谁说的」无法被查询、合并、或赋予它自己的属性。
- 没有「人民日报社（组织）出版 人民日报（非人实体）」这层结构，而这是证据可信度
  分级的基础。

### 1.2 目标模型

五类节点，其中四类是「基础实体」，第五类是证据：

```
person        人物        张澜、习近平
thing         非人实体    人民日报、史记、某份条约、某部法律
organization  组织/国家   人民日报社、中国共产党、东汉、最高人民检察院
event         事件        阪泉之战、女娲造人、某次会议
evidence      证据        某次记载 / 某篇文章 / 某条口传
```

关键约束（用户明确要求）：

1. **组织与国家是同一类**。东汉、西汉、秦朝与人民日报社、黄巾军共用 `organization`。
   不设独立的 `state` / `polity` 类型。
2. **证据的主语必须是已注册实体**。一条证据说「人民日报 1978年5月11日刊载《实践是检验
   真理的唯一标准》」，则：
   - 主语（载体）= `人民日报`，是 `thing`
   - 出版者 = `人民日报社`，是 `organization`，通过 `publisher` 谓词指向该 `thing`
   - 被记载者 = 张澜，是 `person`
3. **事件不是证据**。事件是被断言发生过的事；证据是「某处记载了某事」。
   二者关系用 `documents` / `documentedBy` 谓词连接。

## 2. 节点形状

### 2.1 基础实体（person / thing / organization / event）

沿用现有分片形状，不新增必填字段：

```json
{
  "id": "thing:1a2b3c4d5e6f7a8b9c0d",
  "name": "人民日报",
  "type": "thing",
  "aliases": ["人民日报（报）"],
  "props": { "类型": "报纸", "创刊": "1948年6月15日", "出版者": "【organization:...|人民日报社】" },
  "sources": ["evidence:..."],
  "external": {},
  "detail": "entities/thing%3A....json"
}
```

`props['出版者']` 用 `【id|显示名】` 引用语法（已有 `data_store.resolveRefs` 支持）。

### 2.2 证据节点（evidence）

```json
{
  "id": "evidence:9f8e7d6c5b4a39281706",
  "name": "人民日报 1978-05-11 《实践是检验真理的唯一标准》",
  "type": "evidence",
  "carrier": "thing:...",          // 载体实体 id（thing / organization 皆可）
  "documentedAt": { "start": 2443637, "end": 2443637 },  // 刊载/成文时间，JDN
  "accessedAt": "2026-10-17T...",
  "url": "http://...",
  "medium": "newspaper",           // newspaper | book | inscription | oral | archive | web
  "excerpt": "……",
  "reliability": 0.9,              // 0–1，可选，人工标定
  "note": ""
}
```

设计取舍：

- **`carrier` 是实体引用，不是字符串**。证据必须能回答「谁说的」。
- **`name` 是给人看的标题**，可重复；身份由 `id` 决定。`id` 推导见 §3。
- **`url` 与 `accessedAt` 保留**，因为网页证据需要它们；但不再是身份的一部分。
- **`medium` 用枚举**，避免自由文本漂移（与谓词原语同一哲学）。
- **`reliability` 可选且默认不参与推理**。它是人工标注，不是自动评分；
  没有标注的证据按 1.0 处理但标记为 `reliability: null`，以便区分「没标」与「标了满分」。

## 3. ID 规范

沿用现有规范：`type:sha256(type + '\0' + name).slice(0, 20)`，由
`src/store/entity_id.js` 的 `entityId()` 生成。

新增两个导出：

```js
thingId(name)      // entityId('thing', name)
evidenceId(key)    // entityId('evidence', key)
```

**证据 id 的键怎么取？** 这是唯一需要新决定的地方。规则：

```
evidenceId = entityId('evidence', canonicalKey)
canonicalKey = `${carrierName}\u0000${dateKey}\u0000${title}`
```

- `carrierName`：载体实体的**规范名**（不是 id）——因为 `organization:人民日报社` 改名后
  旧证据不应跟着产生新 id。
- `dateKey`：`documentedAt.start` 的 JDN，未知则空串。
- `title`：证据标题。

同一份报纸同一天的两篇文章 → 不同 `title` → 不同 id（正确）。
同一篇文章被两个来源分别引用 → 同 carrier + 同日期 + 同标题 → **同一 id**（正确，
这正是去重所需）。

## 4. 谓词扩展

`registry.js` 的 `domain` / `range` 枚举从 3 值扩到 4 值，并新增证据域。

### 4.1 新增/调整的谓词

```js
// 证据 ←→ 被记载者
{ key: 'documentedBy', label: '见于', domain: 'person|thing|organization|event',
  range: 'evidence', inverse: 'documents', negatable: false, qualifiers: [QUAL.SOURCE] }
{ key: 'documents',    label: '记载', domain: 'evidence',
  range: 'person|thing|organization|event', inverse: 'documentedBy', negatable: false }

// 证据 ←→ 载体
{ key: 'carriedBy',  label: '载于',  domain: 'evidence', range: 'thing|organization',
  inverse: 'carries', negatable: false }
{ key: 'carries',    label: '载有',  domain: 'thing|organization', range: 'evidence',
  inverse: 'carriedBy', negatable: false }

// 非人实体 ←→ 组织
{ key: 'publisher',  label: '出版方', domain: 'thing', range: 'organization',
  inverse: 'publishedBy', negatable: true }
{ key: 'publishedBy', label: '出版', domain: 'organization', range: 'thing',
  inverse: 'publisher', negatable: true }
{ key: 'author',     label: '作者',  domain: 'thing', range: 'person|organization',
  inverse: 'authored', negatable: true }
{ key: 'authored',   label: '著作',  domain: 'person|organization', range: 'thing',
  inverse: 'author', negatable: true }

// 事件 ←→ 参与者（补全四类之间的全连接）
{ key: 'participant', label: '参与者', domain: 'event', range: 'person|organization',
  inverse: 'participatedIn', negatable: true }
{ key: 'participatedIn', label: '参与', domain: 'person|organization', range: 'event',
  inverse: 'participant', negatable: true }
{ key: 'occurredAt', label: '发生地', domain: 'event', range: 'thing', negatable: true }
```

### 4.2 domain / range 的多值语义

`'person|organization'` 表示该谓词接受其中任一类型。校验时按 `|` 分割再比对。
`literal` 仍是特殊值，表示对象不是实体引用而是自由文本。

## 5. 迁移路径

分五步，每步都可独立验证、可回滚。

### 步骤 1：新增 `thing` 类型（不改存量数据）

- `FOLDERS` 加 `thing: 'things'`
- `entity_id.js` 加 `thingId`
- `data_reader.js`、`build_index.js`、`check_manifests.js`、`graph_source.js` 同步
- 创建 `data/things/{entities,index,search}` 目录骨架
- 验收：`npm run check` 全绿，`data/things` 有 0 个实体但 manifest 合法

### 步骤 2：新增 `evidence` 类型与节点形状

- `FOLDERS` 加 `evidence: 'evidence'`
- `entity_id.js` 加 `evidenceId(carrierName, dateKey, title)`
- 新增 `src/store/evidence.js`：校验/构造 evidence 节点（纯函数，可单测）
- 验收：新单测通过；库里 0 条证据但类型合法

### 步骤 3：谓词注册表扩展

- `registry.js` 加 §4.1 的谓词
- `domain`/`range` 校验函数支持 `|` 多值与 4 类型
- 浏览器侧 `js/core/predicates.js` 重新生成，一致性测试锁定
- 验收：`predicates.test.js` + `predicates_browser.test.js` 通过

### 步骤 4：存量 `sources` → `evidence` 节点迁移 —— ✅ 已完成

这是**唯一会触碰 5287 个存量实体**的一步。做法：

1. 扫描所有实体的 `sources[]`，按 URL 归并
2. 对每个唯一 URL 建一个 `evidence` 节点：
   - `carrier`：从 URL 主机推断（`carrierFromUrl`）；无法推断则标 `unresolved: true`
   - `title`：原 `sources[].name` + URL 尾部
   - `documentedAt`：未知则留空
3. 实体侧 `sources` 从对象数组改为 **evidence id 数组**
4. 保留旧的 `sourceUrl` 边限定符不变，避免破坏图查询

脚本：`tools/oneoff/migrate_sources_to_evidence.js`。

**结果**：124 条内联 source → **111 个证据节点**（去重 13 条同 URL 重复），
82 人 + 6 thing + 4 organization 的 `sources` 全部改为引用，**0 悬空引用、
0 残留内联对象、0 未解析载体**。

#### 两个必须记住的坑

**坑一：证据 ID 不能只用 `sources[].name`。** 旧数据的 `name` 是*站点标签*
（「人民网人物资料」「全国政协官网」），不是文章标题。按名字作身份会把上千个不同
页面折叠成一个节点并丢掉其余 URL——首次执行时 111 个只落地了 9 个。现在标题
包含 `host + path`，同 URL 仍会去重（这是我们想要的），不同 URL 永不合并。

**坑二：`entity_writer` 默认对 `sources` 做并集，迁移会被静默撤销。** 并集逻辑
使得旧的 inline 对象与新引用共存，再次写入时又把旧对象带回来。已给
`upsertAll(type, records, merge, { replaceSources: true })` 加替换模式。

### 步骤 5：补建证据主语实体 —— ✅ 已完成

| 主机 / 名称 | 实体 | 类型 |

| `www.people.com.cn` | 人民网（主办：人民日报社） | thing |

#### 仍未建实体的标签

4 个标签是抽取遗留物，**不是机构**：

```
（未具体说明）
（未具体说明，但可推断为工作单位）
未具体说明（参加工作）
（未具体说明，指参加工作的时间点）
```

它们是数据质量缺口，已记录在此。把它们建成节点只会让图上出现占位符，
让「未解析率」看起来比实际更好。

机构标签解析率：**37 个不同标签中 33 个解析成功（89%）**，剩余 4 个即上述占位符。

## 6. 兼容性

### 6.1 必须保持不变的

- `data/<type>/index.json` 仍是生成文件，只有 `build_index.js` 能写
- `entity_writer` 仍是唯一写入口，继续内容感知写入
- `sources` 从对象数组改为 id 数组后，`graph_source` 的 `sourceUrl` 回退链
  要能同时处理两种形态（迁移期）
- 前端 `js/core/data_store.js` 的 `resolveRefs` 语法不变

### 6.2 破坏性变化

| 变化 | 影响 | 缓解 |
| --- | --- | --- |
| `sources` 元素从对象变 id 字符串 | 所有读 `sources[0].url` 的地方 | 加 `src/store/sources.js` 统一解析两种形态 |
| 实体类型 3 → 5 | 前端类型筛选、谓词 domain 校验 | 同步更新并加测试 |
| `数据` 目录多两个 | 构建脚本的 FOLDERS 表 | 单一来源改为从 `src/store/entity_writer.js` 导入 |

## 7. 验收标准

1. `npm run check` 全绿，且**每个类型都有实体**（不允许某类 0 条蒙混过关）
2. 证据节点数 > 0，且每条证据的 `carrier` 若非 null 则**必须解析到已存在的实体**
3. 「人民日报」「人民日报社」「最高人民检察院」等作为实体存在，且
   `人民日报` 的 `publishedBy` → `人民日报社` 边成立
4. 5287 个存量人选中，原先有 `sources` 的那些，迁移后 `sources` 全部是
   能解析的 evidence id（不允许指向不存在的节点）
5. `check_references` 报告的组织标签解析数从 0 上升

## 8. 不做的事

- **不引入新的日期系统**。证据的 `documentedAt` 用现有 `TimeRange` + JDN。
- **不自动判定证据可信度**。`reliability` 只能人工填。
- **不把 event 合并进 evidence**。二者语义不同，见 §1.2(3)。
- **不设 `state` / `polity` 类型**。国家与组织同类，用 `props['类型']` 区分
  （「朝代」「诸侯国」「王朝」「报纸」「政党」）。
